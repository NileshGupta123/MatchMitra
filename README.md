# MatchMitra - AI Cricket Companion

> Don't just show fans the score. Restore the match context they missed.

MatchMitra is a small web app that helps a cricket fan who joins a T20 match late, or looks away for a few overs. It replays a **simulated** T20 chase ball by ball and uses an AI (Groq, `openai/gpt-oss-120b`) to explain what happened in simple words.

**All match data is simulated.** The teams and players are fictional, and this is not a real live match. The page says so at the top.

## The fan problem

A fan opens the app mid-match. The scoreboard says `83/2, need 89 from 60`. It does not say how the chase got there, who is on top, or why the last over mattered. Asking a friend breaks the flow of watching, and scrolling a commentary feed is slow.

MatchMitra answers the questions that fan actually has, using only what has happened so far.

## Features

| Feature | What the fan gets |
|---|---|
| **Catch me up** | The score, the last 5 overs (boundaries, wickets, pace) and who has the momentum, in about 90 words. |
| **Explain this moment** | Pick a wicket, four, six or expensive over from the key moments list. MatchMitra explains what happened and how it changed the chase. |
| **Ask MatchMitra** | Free questions such as "Who has the momentum?". Questions about the future are answered honestly: the AI cannot know what happens next. |

Also included: a scoreboard with current and required run rate, replay controls (play, pause, speed, slider, jump to an over), and a ball-by-ball view of the recent overs.

## How it works

The key design rule: **Python calculates, the AI only explains.**

1. The page sends the current replay position (a ball index) to the API.
2. `match_logic.py` takes only the deliveries up to that position and calculates every fact: score, run rates, partnerships, per-over runs, momentum, key moments.
3. `prompts.py` wraps those facts in a prompt with strict rules (use only the data, no invented facts, no future events, no arithmetic by the AI).
4. `llm_client.py` sends the prompt to Groq and turns every failure into a friendly message.
5. The page shows the answer with the position it refers to, for example "As of 83/2 after 10.0 overs".

Protections:

- **No future context for the AI.** `get_balls_upto()` is the only place the replay position is applied, and every calculation works on that slice. Tests check that the final score and later batters never appear in a prompt.
- **No invented numbers.** Over and ball descriptions such as "ball 3 of the 3rd over" are produced by Python, so the AI never converts cricket labels itself.
- **Questions are untrusted input.** A fan's question is wrapped in markers and the system prompt tells the model to ignore instructions inside it. This reduces prompt-injection risk but is not a complete guarantee.
- **Safe rendering.** AI text is shown as plain text, never as HTML.

## Architecture

```
Browser (static/index.html)
   |  GET /api/match, GET /api/moments, POST /api/catchup | /api/explain | /api/ask
   v
main.py (FastAPI: validation, errors, answer cache)
   |--> match_logic.py   all cricket facts, from the balls up to the replay position
   |--> prompts.py       system prompt and the three task prompts
   '--> llm_client.py    the only file that talks to Groq
            |
            v
         Groq API (openai/gpt-oss-120b)
```

## Technology

- Python 3.12, FastAPI, Uvicorn, Pydantic
- Groq Python SDK (`openai/gpt-oss-120b`, low reasoning effort)
- One static HTML page with plain CSS and vanilla JavaScript (no build step)
- Match data in JSON, generated by a script

## Prerequisites

- Python 3.12 (3.11 or newer should also work)
- A free Groq API key from https://console.groq.com (only needed for real AI answers)

## Local setup

```powershell
# Windows PowerShell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

```bash
# macOS or Linux
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Open `.env` and set your key. Never commit this file (it is in `.gitignore`).

```
GROQ_API_KEY=your_groq_api_key_here
GROQ_MODEL=openai/gpt-oss-120b
```

## Generate the match data

`data/match.json` is already included. To rebuild it:

```
python generate_match.py
```

The script checks that the chase ends on exactly 172/6 off the last ball.

## Run the tests

These work offline. They need no API key and no network.

```
python match_logic.py     # cricket logic and data consistency
python llm_client.py      # error handling with a fake client
python prompts.py         # prints the prompts and checks for spoilers
python main.py            # API tests with a fake AI
```

Live test with your real key (one short call to Groq):

```
python llm_client.py live
```

## Start the server

```
uvicorn main:app --reload
```

Open http://127.0.0.1:8000. API docs are at http://127.0.0.1:8000/docs.

## API endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/` | The web page |
| GET | `/api/health` | Health check (also shows the model name) |
| GET | `/api/match` | Match info and the ball-by-ball replay |
| GET | `/api/moments?ball_index=N` | Key moments up to ball N |
| POST | `/api/catchup` | Body `{"ball_index": N}`. Last 5 overs summary |
| POST | `/api/explain` | Body `{"ball_index": N}`. Explains the moment at ball N |
| POST | `/api/ask` | Body `{"ball_index": N, "question": "..."}`. Answers a question (1 to 300 characters) |

Errors always come back as `{"error": "..."}` with a clear message. Catch-up and explain answers are cached in memory, because they depend only on the replay position. This saves Groq calls and is enough for one small, fixed match. Ask answers are not cached.

## Deploy on Render

1. Push the project to GitHub. Check that `.env` is not included and that `data/match.json` is.
2. On https://render.com choose **New** then **Web Service** and connect the repository.
3. Settings:
   - Runtime: Python
   - Build command: `pip install -r requirements.txt`
   - Start command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
   - Health check path: `/api/health`
4. Under **Environment** add:
   - `GROQ_API_KEY` (your real key)
   - `GROQ_MODEL` = `openai/gpt-oss-120b`

   The `.python-version` file in the repository tells Render to use Python 3.12, the version the tests were run on. Render's own default is newer, so keep this file.
5. Deploy, then open the public URL and try all three features.

On the free plan the service sleeps after about 15 minutes without traffic, so the first request after a pause can take up to a minute.

## Simulated data disclaimer

The match, the teams (Sahyadri Strikers, Konkan Kings) and every player are **fictional**. The data is written by `generate_match.py` to tell a clear story: early wickets, a slow middle, one expensive over and a last-ball finish. It is not a prediction, not a real match and not connected to any betting or fantasy product.

## Limitations

- One simulated match, replayed from a file. There is no live cricket feed.
- The browser downloads the full replay, so a technical user could look ahead. The guarantee is that **the AI** never receives deliveries after the selected position.
- The momentum signal is a simple rule (recent run rate against required run rate and wickets), not a prediction.
- Wicket entries name only the bowler, so MatchMitra cannot say who took a catch.
- AI wording can vary between runs. Facts come from Python, but the sentences are written by the model. Prompt rules reduce mistakes without removing them.
- Free-tier hosting is slow on the first request after a pause, and Groq's free plan has rate limits.
